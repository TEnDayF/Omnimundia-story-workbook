# 原创示例：雨灯驿站

供 [Omnimundia](https://omnimundia.cn/) 十表剧本制作使用的原创示例。Excel 模板请自行到该网站导出，本仓库不提供。

一个没有骰子的送达短篇，用于演示十表的内容归属，而非平台能力证明。
本目录只提供 JSON 内容示例，用于阅读和版本比较；它不是网站导入模板。请按自己从网站导出的模板填写。

## 读法

先读开场，再看实体属性和词条，最后读世界背景中的幕后规则。
玩家可见物品有唯一归属；后台流程永久隐藏；路线知识在问询后解锁。
未采用的随机机制、结果区间、持续状态、循环事件和预设行动只保留表头。
日期是故事中的虚构时间。教学示例不使用真实个人资料或原样表的剧情。

## 设计核验路线（不是实机记录）

| 路线 | 行动与时间 | 期望结果 |
| --- | --- | --- |
| 石桥 | 18:00问询5分 → 取灯芯5分 → 步行25分 → 18:35交付 | 灯芯移出库存，灯窗亮起一次 |
| 小船 | 问询5分 → 取灯芯5分 → 检查木箱并取绳5分 → 绑桨5分 → 划船15分 | 18:35到达；绳留在船上，交付只计一次 |
| 拒绝 | 开局明确拒绝 | 灯芯留在柜台；任务结束，无自动送达 |
| 延误 | 19:00之后才交付 | 允许交付，但不触发按时灯窗事件；本夜渡船停航 |
| 重复 | 交付后再次请求交付 | 无重复灯芯、事件或奖励 |

这些是静态情境推演的预期。真实平台需要分别检查导入、保存回读、知识解锁、物品移除和时钟更新。
空触发时间是否支持条件事件须在目标平台核实，必要时按平台格式迁移，不能把结构校验当成兼容证明。
