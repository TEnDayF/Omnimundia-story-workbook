# 篇幅、文笔与真实试玩

## 先读取参考本，再定义篇幅

用户说“按第一个本的字数”时，从所给最新文件提取实际规则并记录位置，不沿用旧的 2000–3000 字口径。某次参考为目标 1000–1600、最低 800，只能作为该次规格，不能成为普遍默认值。明确数字计的是纯正文、汉字、非空白字符还是含标点字符；选项、状态栏、重复日志不应充当正文凑字。

避免互相矛盾的指令，例如同时要求极短、快速结算、达到决策点立即停止、每轮大量字数，而不给停顿前的展开空间。把重复规则整理成一处主规则，必要时在生成末尾做简短完整性检查；重复和末尾检查在部分实例有效，但不是模型必然服从的保证。

信息公开与玩家权限同时遵守[自然叙述与认知边界](narration-and-knowledge.md)；平台回读、计时与存档证据见[运行验收](runtime-acceptance.md)。

## 在决策点前扩展，不越过决策点

一个回合应在当前授权行动与当前场景内展开：
1. 可感知环境发生什么变化，它如何影响正在进行的动作。
2. 行动的具体过程：距离、姿态、节奏、阻碍与即时反馈。
3. NPC 根据自己的目标、性格和信息产生反应；用停顿、视线、手势与不同语气体现差别。
4. NPC 可以解释、追问、争论、提出条件或主动带来可介入事件。
5. 在真正需要玩家选择的地方停止，给出当前可做的行动意图。

以上是检查维度，不是每轮必须照抄的五段格式。对白来回必须属于 NPC 的合理互动和玩家已说内容的回应，不替玩家编造答复。不要靠重复同一个眼神、景物或刚发生事件扩字。更长的篇幅应新增有效感受、关系变化或可操作线索。

主动推进可以由 NPC 的需求、环境变化、已有后果、可拒绝邀请与时限构成。不能替玩家决定心理、感情、承诺或连续未选行动，也不能用“为了推进”强迫接受任务。选项描述尝试做什么，不提前写成功、奖励和隐藏结局。普通行动选项的朴素措辞可以按项目要求保留，不意味着正文也必须短促。

不要直接暴露后台判定、计数、生成要求；避免全知未来句式及生硬战报总结。动作的效果要符合既有能力与位置，不能为了细节临时发明装备机理。

## 对照测试

记录一条样本至少包括：版本/修订号、开局身份、模型与设置（可见时）、轮次、玩家原输入、正文原文、字数口径与实际值、选项、关键实体前后值、缺陷、复测结果。不要凭肉眼估算或把多个版本的优秀样本混成当前版成绩。

- 基线：旧版或修改前的同类自然行动；尽量保持开局、设置、输入和场景相当。
- 新版：用“看看周围”“问对方怎么了”等自然行动测试，不在玩家输入里加“写满 X 字”来掩盖后台规则失效。
- 覆盖：安静探索、对话、危机/战斗、过渡与已有记忆回访。样本数按发现的问题和风险决定，不用一轮成功宣称稳定。
- 同时验收长度、有效细节、角色差异、介入空间、剧透与状态一致性。长度达标而内容重复或抢玩家行动，仍不合格。
- 如使用调试开局或构造状态，标明构造测试；结束后核对调试关闭、时钟与角色状态恢复。构造战斗验证不能代替自然主线节奏和平衡验证。
- 测试没有覆盖死亡分支就写“未测”，不能因为核心流程通过就算死亡复活边界通过。S 级规则只有静态阅读则只报静态检查。

迭代流程：识别可重现缺陷 → 最小修改 → 保存回读 → 重测同一缺陷 → 补测相邻场景。目标是达到约定体验与验收项；遇到授权、额度或平台阻碍时报告真实进度，不声称“已全线玩通”。
