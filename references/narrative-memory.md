# 长剧情纪要与检索实体

用于用户要求逐轮记录、阶段总结或缓解长剧情上下文丢失。它是可选的运行机制，不给所有短剧本自动添加；总结周期采用当前项目要求；15轮仅在明确选用时适用，不设跨项目默认周期。它依赖网站实际保存并向AI提供实体信息，写入提示词不等于已实现持久化或自动检索。

隐藏记录的可选四实体结构及开局知识见[状态与记忆](state-and-memory.md)。以下单实体七属性用于已选用的可见旅程日志，不要求将现有文件迁移到任一结构。

## 预置实体与信息归属

在“实体与属性”中预置一个“叙事纪要与检索系统”辅助实体，是否玩家=否。参照玩家可查看的旅程日志时，是否隐藏=否；全部名称、初值、规则及后续总结都遵守玩家当前认知。它不是世界中的人物，不参与行动，不泄露后台秘密或未来情节。

建议用7项属性，已有等价字段则复用：

| 属性组／属性 | 初始值 | 实际更新规则 |
| --- | --- | --- |
| 介绍／简介 | 简述回顾旅程和查找历史的用途 | 不保存具体剧情或预告 |
| 运行／已记录轮次 | 0 | 每次有效推进完整记入后加一；重试不重复计数 |
| 运行／已整合至轮次 | 0 | 对应总结保存并核对成功后，更新为该段末轮 |
| 记录／近期逐轮纪要 | 尚无记录 | 每轮追加已发生且已知的行动、结果与重要变化 |
| 总结／阶段目录 | 尚无阶段 | 每段总结保存后追加范围、时地、关键词与属性名 |
| 总结／长期要点 | 尚无要点 | 保存仍有影响的经历、关键选择与约定，注明来源轮次 |
| 记录／未结事项 | 尚无事项 | 跟踪已接受任务、承诺和待查线索，实际解决后标明结果 |

完整执行顺序和动态阶段属性模板写在世界背景。纪要记录历史，人物及物品实体保存当前状态；优先复用现有任务与承诺记录，纪要只存来源索引或简述，避免另立不一致的当前状态台账。词条库保持固定，不用词条承载逐轮日志。

## 每轮记录与项目周期整合

1. **定义轮次**：一次玩家行动得到实际剧情结算算有效一轮。角色创建、纯设置、刷新、失败请求不计；重新生成同轮回复更正最终保留记录，不重复追加。区分平台页面回合号、有效轮数和世界时间，不把15轮换算成15分钟或日期循环事件。
2. **先结算再记录**：更新当前实体，再写“第N轮｜时间｜地点｜人物｜行动与实际结果｜关键变化｜未结事项”，完成后更新已记录轮次。通常80—160字，无变化的项目省略；关键物名称、代价、承诺、证据来源和不确定性优先保留，不用硬字数截断。
3. **达到周期才创建总结**：按项目周期K划分1—K、K+1—2K等范围。在同一实体的总结组新增“第K阶段纪要（第A至B轮）”，不预置未来空阶段。通常250—450字，包含时间跨度、地点迁移、关键因果、决定与后果、未结事项及来源轮号；实际长度以信息完整为准。属性规则须非空，限定该段已发生事实及有依据的更正。
4. **保存后才合并**：先保存总结，核对关键线索、唯一物转移、伤势代价与约定没有遗漏，再更新目录、长期要点及整合标记，最后移除近期区中已纳入总结的明细。保存失败或证据不足时保留明细及旧标记，下轮补整；同一范围已存在则核对或更正，不创建副本。用户要求保留所有明细时遵从，并说明记录增长。
5. **保留阶段与分支边界**：旧总结不被新阶段覆盖。发现早先误解时追加来源与更正依据，不改成当时已知真相。回滚、分叉后只沿当前世界线续记；旧档接入从可核实的记录接续，缺失历史保持缺失。总结不推进下一轮、不替玩家完成未结事项。

## 回读与长程增长

每轮生成前读取近期纪要、长期要点和未结事项。涉及旧人物、地点、物品或约定时，按目录关键词回查相应阶段，再核对当前实体。旧纪要不能使旧伤势、旧归属或已结束任务再次生效。传闻、亲历与推测分别标明，不把NPC未公开心声写成“人物回忆”。

规则要求AI回读平台实际提供的记录，不虚构搜索API或声称已读到无法访问的旧记录。摘要缺少决定性细节时说明不确定性，按现有证据继续；不能凭空补史。记录操作在后台完成，正文自然接续，不逐轮展示维护过程，不让NPC谈论系统轮数。

周期总结只降低明细增长，阶段档案仍会累积。根据实测的实体长度与上下文提供方式再决定是否增加更高层汇总或独立归档；不要默认无限保存或宣称彻底消除遗忘。高层摘要不能代替原有关键证据和索引。

## 完成检查

至少检查项目周期K的第K−1→K→K+1轮、同轮重试、总结保存未完成、旧承诺被新事件履行这几种情境；确认不漏轮、不重算、不提前推进、不泄密，历史与当前状态不冲突。已有世界线接入须验证可用起点，不能以新文件替用户补造记录。

区分规则推演、文件结构及文字复读、网站运行验证。未实际在网站验证逐轮写入、阶段保存和历史回读时，交付明确这一限制；成品工作簿字数上限也不代表游玩产生的日志会永久保持该大小。

为有效回合保存稳定ID及最近提交ID；同ID重试替换或保持原事件，物品、伤害与轮数只结算一次。总结前保存可恢复检查点并回读，再压缩旧明细。回滚同时恢复剧情和状态。平台不支持事务、检索工具或原子保存时，这些是提示约定与验收项，不能声称具备代码级保障。
