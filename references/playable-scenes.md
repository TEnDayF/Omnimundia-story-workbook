# 可行动的场景与平台试玩

用于原创开局、自由行动、选择后果及网站试玩反馈。它补充场景设计和实测方法，不改变十表字段；信息归属仍以 [表格结构](workbook-schema.md) 为准，公开出口仍以 [认知边界](narration-and-knowledge.md) 为准。

## 先做出一个能玩的场景

从用户已有资料提取以下六项，只补影响当前交付的缺口。用户授权自主创作时直接设计并记录依据，不把本表变成六轮必答问卷。

| 项目 | 可执行的完成标准 |
| --- | --- |
| 角色目标 | 玩家知道此刻想完成什么，能提出第一步行动；宏大使命之外有眼前需要。 |
| 可见现场 | 交代地点、在场者、可观察的阻碍和现有资源；信息足够行动，不先讲完世界史。 |
| 稳定规则 | 决定后果的世界规律前后一致。未知规律可以被调查，但承担已知不可逆代价前须提供足以判断风险的线索。 |
| 人物动机 | 关键NPC有自己的目标、顾虑和合作条件，能基于事实答应、讨价还价或拒绝。 |
| 可选行动 | 不同策略至少会改变一项有意义的时间、资源、关系、信息或身份；开放玩法保留符合规则的自由输入。 |
| 收束条件 | 明确眼前问题何时解决、失败或暂时结束，结算后保留所得与代价；后续从剩余因果生长。 |

首场在玩家能改变事情之前交还控制。角色介绍、问卷和环境描写可以服务首场，但不能替代它。回合长短按决策需要确定；视频时长、镜头数和宣传用钩子不是全部互动剧本的默认限制。

## 让选择改变事实

先列出不随路线变化的世界规律，再列允许变化的局面。分别推演采用建议行动、提出合理替代方案及拒绝任务时，人物和场景如何回应。有限路线或忠实改编依用户要求设计，不强制所有作品开放世界。

- 成功由目标、能力、资源、准备和对抗条件支持；合理替代方案可以有效，也可以部分达成或失败。不要把自由输入自动奖励为成功，也不要为守住预定剧情临时宣布所有替代方案失效。
- 获得称号、学会能力、取得权限、接受任务和承担义务是不同事实。只有实际触发相应条件才更新；角色自称某身份或模型复述它，不构成世界已经承认。
- 关键手段需要来源。现场已有物件可利用；新出现的便利工具须符合环境和已有资源边界，稀缺或决定性道具需经过获取，不能在需要时无条件出现。
- 一条路线的后果不污染另一条路线。例如从未接下委托的角色，不应在后续被记录为“任务失败”。已修复的障碍也不因需要续写而原样重置。
- 给局部事件一个完成点。若通道已疏通且交接已完成，就承认本次目标完成；下一件事以新的原因开始，不不断追加同类障碍拖延结算。长篇可以开放结局，当前行动仍需有实际反馈。

示意：大厅入口被石台挡住，玩家希望清路。世界允许符合条件的人取得称号，但任职另需本人同意。拔出道具后移台、协作搬动整座石台可以产生不同身份结果；两者都按现实负重、人员与耗时判断。此例只解释“目标、手段和身份分开结算”，不向其他项目复制人物、魔法规则或必胜路线。

## 把能力、代价和时序接起来

能力按“触发—所得—限制—代价—持续—恢复”检查。代价必须影响后续行动，而非每次只在旁白里疼一下。恢复条件要区分主动修复、自然经过时间及例外；没有采用数值机制时使用可判断的叙事条件，不补造点数。

例如作者采用“听取旧物残留声音后双手暂时僵冷”的能力，应明确听取能得到什么、不能得到什么，手冷影响什么操作，以及何时恢复。公开固定原理归词条或公开规则，当前手部状态归实体或已采用的持续状态，后台裁定归世界背景；不为此强制填满随机、循环等全部表。

对每次行动同时核对正文、面板时间、当前位置、库存、能力、任务和状态。区分三种时间：作品内日期与钟点、行动经过的时长、现实存档时间。模板的学生身份、年龄、历法或默认日期需要逐项判断是否适用于新作；保留合理的原始值，替换不适用的示例残留。提示词中的字数上限和一致性要求属于写作约束，不代表平台已强制执行。

## 把题材调性落实为裁定边界

“日常”“轻喜剧”“温情”等标签不能替代具体规则。用户选择某种调性时，在世界背景写清常见事件规模、允许的代价、人物反应方式和局部结束点；依现有字段安放，不新增工作表。轻喜剧可以围绕时间、面子、小额花费、误会和互相帮助递进；若当前目标只是取件或吃饭，不为续写自动加入重伤、追杀或宏大阴谋。严肃题材则按用户设定保留必要风险，不把此例变成全部作品的低风险要求。

冲突从不同人物各自合理的目标产生。让关键NPC有具体顾虑、擅长与不擅长之处，能接话、反驳、误解、补台或拒绝；不能只用“微微一笑”消耗玩家提出的互动，也不能让所有NPC为衬托玩家而失去判断力。若采用幽默，让误会有可见依据，包袱由行动后果和反应形成，不靠旁白宣布好笑。

玩家输入的事实、角色开玩笑的台词、尝试的行动和未确认的猜测要分开。例如玩家说“谁的包裹又自己换位置了”，并注明只是玩笑，不能仅凭这句话确认包裹具有移动能力；是否真的异常仍按已有规则与场景裁定。不要擅自添加会限制玩家选择的身世、心理判断、承诺或下一步行动。用户授权自动扮演、预设固定主角或指定叙述视角时，以该授权为边界。

重复劳动和已确定的流程可概括。把主要篇幅留给新的信息、人物回应、可观察变化和需要玩家决定的节点；具体篇幅按玩法需要，不用冗长感官描写挤走行动权。试玩时同时检查调性、玩家控制权和状态面板，而不只检查故事是否续写成功。

## 已获授权时才做平台实测

制作或修订本地Excel不自动授权登录、上传、消费积分、创建剧本或发布。用户已给出的范围持续有效；在项目记录中保存允许访问的剧本、创建数量、修改边界、时间与消费限制，之后沿用。特别是限定只创建一个草稿时，所有创作探查继续使用同一草稿，不能为重试再建副本。

按任务风险选最少但有辨别力的探针，不为了覆盖所有功能消耗积分：

| 探针 | 核对什么 |
| --- | --- |
| 开局与预设行动 | 选项或预设是填入输入框、立即提交还是触发固定结果；新版本实际使用了哪组初值。 |
| 合理自由行动 | 结果基于已有规则和资源，且在新决定出现时交还行动权。 |
| 同一起点的不同路线 | 读取同一版本、同一初始存档后再选择另一行动，比较实际状态；仅重命名或多存一次不算验证分支。 |
| 身份与任务边界 | 拒绝任务、未获能力、无依据的自我宣称不会被自动登记为接受或取得。 |
| 代价与恢复 | 本轮付出在下一轮仍有影响；满足恢复条件后正确解除，无重复扣除资源或发放奖励。 |
| 局部收束 | 达成条件后承认完成，后续引用保留本路线实际发生的事实。 |

操作以当前可见页面为依据，等待一次推演结束再继续；出现验证或限制按平台正常流程处理，不规避检测。重要对照起点和结果使用平台正常手动保存功能；先读取当前自动存档保留提示，不假定自动档永久保存。存在用户限制时不覆盖已有存档。

每次测试记录：日期、剧本/版本、起点、精确行动、期望边界、实际正文与状态变化、积分前后值、保存位置、尚未覆盖项。少量随机生成样本只能支持“此处观察到”，不能证明所有玩家、模型或版本都稳定如此。复现失败时先检查版本是否生效、起点是否相同、前一行动是否授权额外行为，再修改对应规则。

## 平台观察的有效范围

2026-09-28 对 [Omnimundia](https://omnimundia.cn/about) 的少量界面与游玩观察：编辑器提供世界规则、实体属性、状态、事件、词条和预设行动入口；一次测试中预设行动先填入可编辑输入框；同一起点的两种行动产生了不同的身份状态；存档弹窗提示自动存档数量有限，应手动保留重要进度。另见个别叙述与面板钟点不一致，以及生成篇幅超过写作约束的现象。

这些是带日期的观察，不是接口契约。只有入口可见的功能不能写成已验证运行；没有通过导入往返验证时，不能由界面标签推断Excel类型代码、隐藏语义或字段变化。十表结构与能力有争议时，保留现有已确认规范并核实当前目标平台，不凭单次生成重写结构。

## 需要宣传改编时

先确定是忠实游玩实录、经剪辑的游玩故事还是另写短剧情，交付时标清。改编视频可以压缩语言与镜头，但需保留导致结果的规则、人物动机、选择及代价；不把另写的结局标成已发生的运行结果。公开试玩入口须是实际可访问版本，草稿存在不等于公众可玩。营销题材、平台时长和增长指标留在宣传方案，不写成剧本技能的通用世界法则。
