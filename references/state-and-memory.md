# 动态实体、长局记忆与物品

## 隐藏叙事记录

平台确实支持隐藏实体时，可采用实体组“叙事纪要与检索系统”，下设“介绍、运行、记录、总结”四个隐藏实体：
- 介绍：该系统目的与记录边界。
- 运行：有效回合计数、最近已提交回合 ID、总结检查点及版本。
- 记录：已实际发生事件及变动的简明记录。
- 总结：已核实的阶段因果、重要承诺、未解决线索与当前状态。

这是可选结构；现有文件可能仍是可见日志版本，必须检查实际隐藏标记并确认平台读取，不能根据旧记录说已迁移。用户只要求文笔/字数时不扩改该机制。

有效回合、稳定ID、总结提交、回滚及回读统一按[纪要运行流程](narrative-memory.md)执行。隐藏与可见日志采用同一流程，各自遵守实际可见性；提示规则不等于数据库事务或权限隔离。

## 实体与物品栏

按用途分组，避免一项巨大文本承载所有状态。至少区分角色状态、关系/已知信息、装备与背包、任务/线索、世界状态；采用模板支持的组织方式，不为分类增加不兼容列。

物品有稳定 ID，并按需记录名称、数量/单位、拥有者、实际持有者、所在容器/地点、装备状态、耐久/充能、来源与用途限制。拥有和携带不同，仓库存量不等于随身可用。转移、丢失、使用、制作和奖励必须有实际事件依据。

- 消耗只扣一次；同回合重试不能重复扣除或领取。
- 堆叠规则明确，同名不同状态物品不能错误合并。
- 回复叙事不能自动刷新弹药、药品、耐久或货币。
- 战斗结算、交易与背包同步；不能手中和背包各算一份。
- 未知物品可用玩家可见的暂名；隐藏效果不提前显示。

## 开局知识

按所选身份、生活经历、地理范围和公开传播渠道初始化“知道什么”。知名主线人物可有公开职务、常见形象或传闻；公开知名度不赋予私人动机、真实能力上限和未来路线信息。传闻注明尚未确认。维护世界事实与角色已知事实的分离，并在实际获知时更新动态实体。
