# 表格结构与拆分

目标网站：[Omnimundia](https://omnimundia.cn/)。此文档描述该网站剧本制作所用的十表约定；当前兼容性以网站实际导出与回读为准。

字段、顺序和列宽以同目录 [schema.json](schema.json) 为准。以下规定描述本工具包所用的十表格式；用户提供不同的目标平台结构时，以其明确要求为准并记录差异。

## 固定的10张表

| 工作表 | 内容与写法 |
| --- | --- |
| 基本信息 | A1/B1为“字段/内容”，A2至A9依次是版本名称、版本描述、开局时间、世界背景、骰子检定、玩家自主开关骰子检定、固定开局、玩家自主开关固定开局。世界背景在B5，保留段落。开关值参照“默认开启/默认关闭”“允许/不允许”，选择由用户确认。 |
| 固定开局选项 | A1写“固定开局描述”、B1写开场正文；A2/B2为“选项/后果”，第3行起每行一个选项及其后果。开局选项数量与普通回合数量可以不同。 |
| 随机机制 | 一行一个已采用的骰子机制，写清生效时机、骰子数量、面数、修正值；没有机制时仅保留表头。概率本身不自动等于必须增加一套骰子。 |
| 随机项结果区间 | 用“随机项名称”准确关联随机机制；最小和最大值均包含边界。问清按原始点数还是加修正后的结果判定。区间应无意外重叠与空缺；例外需明确。 |
| 实体与属性 | 一行一个属性，完整重复实体组、实体名称、是否玩家、是否隐藏、属性组。实体唯一键为“实体组+实体名称”，属性键再加“属性组+属性名称”。初始值与变化规则分列。 |
| 持续状态 | 保存当前已生效的持续特质或状态；到期时间可空代表未设固定到期，但须在描述中解释解除条件或持续性。 |
| 循环事件 | 保存确实有周期的事件，频率单位、频率值、下次触发和到期信息互相一致。战斗第N回合的局部效果若平台不支持回合周期，应写进已确认的战斗机制，而不擅自换算成钟表时间。 |
| 一次性剧情点 | 标题、描述、触发时间。描述只分“触发剧情：…”与“触发条件：…”。触发后玩家才看见标题及描述，正文只交代触发当下的场景或已经成立的变化；完整后续、解法与分支放世界背景，以同名或内部映射关联。条件引用也须检查泄密。同一日期不代表同一剧情顺序，过去日期也可能是平台的条件触发标记。 |
| 词条库 | 词条标题、描述、初始可见、显示顺序、图片标识。顶层标题无前缀，下一层为一个全角空格加“┝ ”，再下一层增加一个全角空格。显示顺序按同父级排序，不是全表唯一编号。图片标识无素材可留空。 |
| 预设行动 | 名称、内容、说明、类型。仅填已确认且平台支持的行动类型；无固定行动时保留表头，不虚构类型代码。 |

## 信息归属

先判断信息会不会随游玩改变，再判断玩家是否需要获知。不要只按“隐藏”决定放在哪张表。

| 信息 | 保存位置 | 可见性与更新 |
| --- | --- | --- |
| 健康、位置、库存、关系状态、任务进度等可变信息 | 实体与属性 | 玩家需查看的实体永久可见；只供后台追踪的实体永久隐藏。写明初始值及非空实际规则；可见实体规则避剧透，隐藏实体规则可含完整幕后逻辑。 |
| 名称含义、固定身世、能力原理与上限、地点结构、异境固定规律等玩家可获知的信息 | 词条库 | 已知信息初始可见；未知信息初始隐藏，在接触相关信息后解锁。词条内容保持固定，当前值另存实体。 |
| 玩家无需得知的完整谜底、生成模板、NPC后台动机、叙事约束与幕后裁定规则 | 世界背景B5 | 保留AI推演资料，不自动展示给玩家。可变执行进度仍从实体读取。 |

例如：“某能力负荷4时产生劣势”是固定规则，放机制词条；“当前负荷4”是实体值；“后台如何选择对手策略”放世界背景。地点结构是词条；门是否已经打开是实体。人物固定身世若将来可以发现，放隐藏词条；当前合作关系放实体。

混合段落拆为固定定义、可变当前值和幕后规则。实体名与必要引用标识用于识别记录，不需要为此复制整份静态人物档案。自定义主角的开局设定方法放世界背景；角色创建后的自定义经历与身份记录放实体；只有制作表格时已经编定且符合当局事实的固定资料才可解锁，不能在运行中补建角色词条。后续衣着、伤势和关系变化写实体。不要为了保留错误分类而把本来固定的信息描述成可变。

词条库在制作时编定；游玩中正文和名称固定，不能新增、改写或补全，未编入就是没有。初始不可见不是永久不可见，在遇到相关资料并获得足以支持整条介绍的知识后解锁；解锁只改可见性。分阶段知识在制作时拆为不同固定条目，解锁依据放世界背景。局部线索、误解、推测、认知进度及新事件记录放实体，不能运行时改写半条或创建替代词条。不要因为词条含秘密就把全部隐藏资料移出词条库。

## 属性规则必填，按实体可见性处理

每项属性规则必须有文字，且必须确实对应该属性的更新、判定、增减或边界条件。禁止留空、只写属性释义、无关套话或只写“按规则更新”。引用既有机制时也应写清本属性的实际应用条件。

永久可见实体的规则会被玩家看到：填写公开、无剧透的实际规则，未解锁技能、秘密阈值、幕后动机和未来解法等补充逻辑放世界背景，并保留对象与属性关联。不要通过引用隐藏条目名称继续泄密。

公开值也不等于全知真实值：当前称呼不附未来别名，失联位置只显示最后已知地点，能力与装备不预列待获取项目，待办不从路线目录自动生成。未知真实状态仍记后台。所有输出出口与防预告规则见[自然叙述与认知边界](narration-and-knowledge.md)。

永久隐藏实体及其规则玩家都看不到：直接填写完整的对应执行规则，允许包含幕后逻辑，无需脱敏或迁移。可变当前值也保留在实体。所有后续实体生成模板遵循同样区分。

例如，可见技能属性写“实际完成训练并成功复现后添加，只观看示范不算掌握”；隐藏控制倾向属性可写完整的增长、下降、上限及事件条件。两者都必须是可执行的属性规则。

## 实体与数值的拆分原则

先问“这个值会改变后续哪种判定或状态”，再决定是否数值化。

例如，用户确认角色会积累疲劳并影响施法时，可拆为：

- 实体与属性：角色 → 数值 → 疲劳；初始值、范围、每次施法增加量、休息恢复量、何时影响判定均需确认。
- 词条库：特殊值系统 → 疲劳，说明机制；隐藏机制另注明解锁条件。
- 随机机制：仅当用户选用骰子时，增加相应判定，并明确疲劳怎样影响概率或修正值。
- 持续状态：达到已确认门槛后才产生的疲惫效果，写清附加条件与解除条件。

不是每个数值都要拆成四处。当前值由实体表持有，公开规则由已解锁机制词条或无剧透属性说明持有，可见实体的秘密补充规则由世界背景持有，隐藏实体可直接持有完整规则；状态表只在需要持续效果时使用。

每个已采用数值应有：含义、所属对象、初始值、上下限或无界声明、增加/减少来源、恢复/消耗、阈值、越界处理、适用例外。缺少作者选择的部分继续问，不能用样本数值填空。

## 可见性和动态角色

本技能所用十表平台的实体“是否隐藏”只有**永久可见／永久隐藏**，不是登场开关；同一实体的所有属性保持一致。词条的“初始可见”则允许初始隐藏后因接触相关信息而解锁。两种隐藏语义不可互换，不能用词条解锁代替创建角色。其他平台若明确支持不同机制，以其已确认能力为准。

| 信息用途 | 放置方式 |
| --- | --- |
| 开局应显示的角色 | 预置实体，是否隐藏=否，放开局已知的可变状态；固定档案另放词条。 |
| 开局不见、后续需要显示的角色 | 不预置隐藏实体；在基本信息B5写后台模板，满足条件后创建是否隐藏=否的角色。 |
| 已登场角色尚未知晓的固定秘密或能力原理 | 玩家以后需要获知的放隐藏词条，接触对应信息后解锁；始终无需告知的留在世界背景。能力掌握程度等当前状态仍放实体。 |
| 始终用于后台追踪的组织、物品或进程 | 可变状态与对应更新规则用永久隐藏实体，生成模板在世界背景；向玩家展示时记录已知状态或解锁相应固定知识，不修改原实体隐藏标记。 |

每个后续角色模板写明：**生成条件、识别与称呼、后台资料、首次可填状态、固定词条及解锁条件、后续状态更新规则**。模板中有资料不等于玩家已知；根据当时实际证据生成字段。未知姓名使用可区分的临时称呼，获知真名后更新同一实体的识别与引用并解锁固定身份词条；重复见面、延迟消息不重复创建。集体见证人应按实际登场的个体分别生成、分别记录认知，不合为全知角色。

迁移预置隐藏角色时，同时检查玩家的关系属性、物品名称、事件结果与选项是否提前泄露姓名。需要延迟出现的关系字段也写入生成规则。事件描述使用“首次接触时创建；已存在则更新”，并清理“解除隐藏”“实体变为可见”等旧逻辑。角色生成、属性添加和词条解锁分别验证。

可选主控先确认替换同一玩家实体还是保留多个实体；固定主控无需复制所有可选角色方案。自定义主角的身份边界和未填字段处理见 [互动改编](interactive-adaptation.md)。

## 已有实体的延迟属性

按实际认知补充信息时：实体已经出现，不代表所有属性必须开局预置。不希望玩家一开始看见的可变信息可以先放世界背景，满足明确条件后才向原实体追加属性。

模板必须包含：目标实体组与实体名、属性组与属性名、可判断的添加条件、添加时的取值来源、非空且对应的实际规则、重复触发处理。继承实体永久可见性，不以隐藏转可见代替属性添加。不预放“未知”“未觉醒”或空白占位来暗示秘密。

首次满足条件才添加；属性已经存在只更新，不重置或重复奖励。若添加前状态已有变化，取后台实际记录或已发生事实，不盲目使用旧初值。玩家必须先知道行动代价，再确认执行；不能等扣除未展示资源后才说明。尚未掌握的技能不因模板存在而可用。已预编的固定身世、能力原理等仍用词条解锁；创建实体、追加属性和解锁词条分别处理，并同步事件与生成模板。

## 剧情点触发与公开

剧情点的触发是公开当前场景的时机，不是整个节点已经完成。表中保持简明的触发剧情与条件，世界背景保留完整原因、人物动机、解法、后续结算和分支重算；不把多幕结局一次显示，也不因防剧透清空剧情点表。日期不替代实际前提。没有发生的未来信息不进入任何公开出口；预先存在且后来可发现的秘密则可以放初始不可见词条。

参考其他平台时先核实其语义；本节描述的是已确认的十表网站机制，不按其他工具的“隐藏”名称推断相同能力。

## 文件格式

导入模板使用Calibri 12号、固定列宽、无合并单元格、无公式、无冻结窗格、无筛选，正文以单元格内换行组织。它是剧本导入表；保持标题、列顺序和层级前缀比增加装饰更重要。不要因为预览中长文本超出列宽就擅自改造成报告。

新数值按平台要求储存：真正需要数值计算时用数字；属性初始值列可存叙事状态文本；字段本身已公开且其未知状态有实际意义时才可写“未知”，尚未获知的秘密属性按延迟添加规则处理。原有年龄或健康以文本储存时，单纯文案修订不要改变数据类型。日期早于公元1000年或有自定义历法时，保留原样字符串，避免擅自转为Excel日期序号。
